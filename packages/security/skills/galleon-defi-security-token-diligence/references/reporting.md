# Reports and repeat reviews

## Deliver a bounded answer

Lead with the answer to the actual decision and the evidence that supports it. For broad diligence, separate token controls, canonical and side-pool custody, tested exit sizes, current versus launch concentration, treasury/rewards, enforceable holder rights and external dependencies. Preserve severity, confidence, evidence coverage and time basis separately. Positive observations elsewhere cannot cancel a critical finding.

Describe a control as absent only within the code/state and search coverage actually inspected. Describe an exit by its quote or simulation conditions. Distinguish an adverse observation from inability to observe. Include the strongest contrary evidence, remaining questions and specific evidence that would change the conclusion. Do not assign a generic safe badge or predict price returns from a review.

Each finding needs a stable ID, exact proposition, scoped contract, observation pin or historical transaction, reproducible evidence reference, decoding basis and coverage. Keep source attribution and raw private evidence distinct: cite official sources publicly, but do not publish a user's account evidence to a repository by default. A prose claim still needs manual correspondence with the validated evidence; a JSON validator cannot prove the prose is accurate.

## Refresh once, compare deliberately

1. Retain the prior structured report unchanged. Confirm the new review concerns the same chain and address and record any changed decision question, amount or search universe.
2. Refresh state through the selected official providers. Match findings and scoped contracts by stable IDs; do not reuse an old observation merely because its summary still sounds correct.
3. Run the offline comparator described in [evidence format](evidence-format.md). Read its changed fields and coverage losses before writing the update.
4. Separate a new observation block from changed economic facts. A new hash at the same height, backward time/height or a provider change needs explicit reconciliation. Historical findings can retain their original transaction basis while present controls need a fresh state check.
5. Treat disappeared evidence, omitted findings and newly unknown fields as unverified continuity. Resolve an old risk only with new evidence explaining why the condition no longer applies; omission is not remediation.

Compare the same exit amounts and route assumptions, concentration denominator and fee period. Otherwise label the observations non-comparable and explain the changed basis. A cleaner output with fewer checks may be lower coverage, not a safer token. The helper reports structural changes; it does not automatically infer economic improvement or decide which risk dominates.

Return new risks, materially changed risks, supported resolutions and unresolved prior findings. Keep the new pin and coverage alongside the comparison. No background monitoring or automatic re-investigation starts unless the user requested a schedule.
