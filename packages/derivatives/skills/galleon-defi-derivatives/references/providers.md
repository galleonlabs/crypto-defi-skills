## Access, costs and key scope

Public market reads are a different capability from account writes. Reuse the user's configured provider; verify auth/quotas for the selected endpoint instead of assuming all SDK methods are free or anonymous. Funding, borrow charges, trading fees, keeper execution fees, oracle updates, RPC fees, relayer charges and fee recipients belong in the plan. Do not insert referral or builder fields.

Boros's official plugin documents a long-lived stdio process with loopback browser callbacks and locally stored delegated credentials. Trading and AMM tools may sign without another browser prompt once provisioned. Adding this server or generating an agent is not routine read setup. For authorized adoption, pin and inspect the package, select exact read tools first, and keep callback/credential handling inside the user's trusted environment. Do not expose a loopback wallet bridge publicly or create a new signer to make a diagnostic pass.

Derive v3's TS README distinguishes trading scopes from sensitive actions: bot keys should have Trade scope rather than Admin. Keys expire at signed expiry; editing off-chain metadata does not establish on-chain revocation. It also warns withdrawals pay the signer, which may be a session key rather than the owner. Verify the exact current contract before a withdrawal or key-lifecycle instruction. Never copy example secrets or ask the user to paste keys.

No API/MCP documentation promises profitable or safe trading. A functioning read, simulation or signer proves only its specific tested boundary.
