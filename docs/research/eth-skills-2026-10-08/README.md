# ETH.sh skills research, 8 October 2026

The directory is a useful discovery source, but its descriptions are not reliable live integration contracts. The highest-value upgrades are explicit provider provenance and access/cost/authority metadata, exact schema-driven unsigned transaction workflows, and independent simulation/settlement evidence. Existing Galleon packs already cover many listed protocols; adding precise operational contracts improves them more than duplicating vendor corpora.

## Evidence and scope

Reviewed every one of the **58 directory entries** from the live `llms.txt`, fetched every linked source, followed official skill repositories and selected current documentation, and retrieved the repository skill bodies and references without installing or executing external code. Repository archives and each extracted skill body have SHA-256 fingerprints. [Provider review](providers.json), [skill document inventory](skill-inventory.json), and [retrieval evidence](evidence.json) preserve the public evidence trail; raw retrieved bodies remain local research artifacts. MCP discovery snapshots, where successful, prove initialization and schema discovery only; no financial, wallet, paid-data, or prepare tools were called.

Consumer-candidate counts are an inventory, not a claim that each document was subjected to equally deep semantic or security review. Deep operational review prioritized the DeFi/wallet/transaction sources that materially affect these repositories; broad unrelated skill libraries were indexed for scope and boundary patterns. Files containing example/test or repository-maintainer procedures are classified separately. Bankr distributes community/provider contributions as well as its own material; Aeon includes intentional malicious test fixtures. No third-party skill directory is automatically trustworthy.

## Verified changes to directory claims

- **Base MCP moved.** The linked Base quickstart redirects to migration documentation. The maintained product is Coinbase **Wallet MCP**, endpoint `https://wallet-mcp.coinbase.com`, OAuth, with approval for writes. Its persistent skill remains `base/skills`, `base-mcp`. Wallet history accepts only the connected wallet or in-session agent wallets, not arbitrary third-party addresses. [Primary docs](https://docs.cdp.coinbase.com/ai-agents/coinbase-for-agents/wallet-mcp).
- **Morpho expanded and stays experimental.** Current MCP is keyless `https://mcp.morpho.org/`. Query tools accept a chain ID or registered slug; get/position/prepare tools require a slug with `supportsRpcTools:true`. Discover chains per session. The directory’s Ethereum/Base limitation is stale. [Primary MCP reference](https://docs.morpho.org/developers/agents/mcp/).
- **Fluid’s linked skill is unavailable.** Both `https://fluid.io/skill.md` and uppercase alternate return HTTP 200 with a page-not-found body. It cannot be treated as a reviewed skill or working resolver reference. Preserve unavailable status until a canonical replacement is found.
- **Steer is no longer wholly read-only.** Public package `@steerprotocol/cli@4.7.3` documents IPFS artifact publication, unsigned pool/strategy/vault preparation, and optional browser-wallet handoff. Only selected command groups remain read-only. [Public package metadata](https://registry.npmjs.org/@steerprotocol/cli).
- **JAW’s maintained organization changed.** Current documentation names `JustaLab-co/jaw-skills`; the earlier `JustaName-id` source redirects. [Primary LLM docs](https://docs.jaw.id/llms).
- **Sugar release and embedded runner differ.** The directory points at `v0.4.2`; its bundled skill still describes a `v0.4.1` runner pin. Review the runner and help before replacing the existing reproducible pin. [Exact tagged skill](https://raw.githubusercontent.com/velodrome-finance/sugar-sdk/v0.4.2/.claude/skills/sugar/SKILL.md).
- **WalletConnect’s beta README differs from current npm.** The repository describes beta v0.1.x while the three packages publish 0.8.5. Treat package metadata and pinned command help as version authority. More materially, insufficient target-chain ETH in pipe/agent mode can trigger automatic bridging; a transfer request does not imply bridge/spending authority. [Upstream README](https://github.com/WalletConnect/agent-sdk).
- **Official names require qualification.** hypurrclaw Hyperliquid CLI, ETHCF research aggregation, gskril Ethereum utilities, PraneshASP Foundry MCP, z80dev Cryo, and trustless-ai tools are third-party/community surfaces. Their documentation can be authoritative for their software, but they do not become official protocol services or accepted Ethereum standards through directory listing.

- **Alchemy simulation APIs were deprecated.** The [canonical simulation reference](https://www.alchemy.com/docs/reference/simulation) and asset-change endpoint mark 30 September 2026 as the deprecation date. CLI documentation still advertises simulation commands. Treat that disagreement as an unresolved capability gap; an old recipe does not establish a working supported backend.

## Operational requirements for the release

1. Keep Boomkin’s installation catalog restricted to reviewed Galleon sources. Introduce a separate source-reviewed provider discovery catalog. Distinguish keyless public reads, account/quota reads, paid x402 requests, unsigned construction, signing/delegation, publication/admin writes, and independent runtimes. Do not execute directory install strings or connect wallet servers by default.
2. Prefer current official MCP/CLI/SDK surfaces, narrow reviewed tools, untrusted provider content, no automatic prompts/resources. Discover live schemas and retain reviewed capability/surface fingerprints rather than assuming a README’s tool count is a contract. Generic RPC/API/code-execution tools require tighter operation restrictions than name allowlisting.
3. Make signer-free planning concrete: deterministic amounts and units, live deployment/ABI provenance, exact calldata target/beneficiary/spender, approvals in order, slippage/deadline/caps, payload fingerprint, block/time and state overrides. Simulation must use the exact transaction and cannot prove signature, balance, permission or nonce readiness if those were bypassed.
4. Make final evidence concrete: source receipt is separate from destination bridge delivery; order acknowledgement is separate from fill; queued redeem/deposit is separate from available balance; typed-data signature is separate from authorization acceptance. Reconcile transaction/order ID against live terminal position, recipient token and amount.
5. Broaden protocol-specific skills through precise references and adversarial behavioral fixtures, keeping packs independent. The proposed agent package should complement lending, routing, LP, security, payments and governance without becoming a signer or a copied harness/runtime.

## Sharp protocol contracts worth retaining

**Aave:** amounts are main-unit decimal strings. Resolve V3 market/token/chainId or V4 reserveId live. Inspect the actual wallet before preview; build the same parameters previewed. Error-level warnings block a signing handoff, and warning-level messages reach the user. Supply is not collateral unless enabled. V4 `get_transaction_processed` requires the build’s operations array and cannot confirm an arbitrary hash; the protocol feed lacks block/gas/receipt data. Unfiltered V3 market reads cover Ethereum alone, whereas symbol-filtered discovery is cross-chain. Report covered/not-read/not-served chains, sample versus population, capacity and recent rate range. Do not generalize a limitation of the server’s V3 repay-with-collateral route to the entire protocol. [Official skills](https://github.com/aave/skills).

**Morpho:** `PreparedOperation` includes transactions, requirements, outcome and warnings; approvals in requirements are already in transactions. Error severity blocks presenting the payload for signing. Vault APY is realized average, market rates are 24-hour averages, percentage strings exclude rewards. V2 performance fees charge interest; management fee APR applies to assets. Query and position pagination must be exhausted or reported partial. [Tool contract](https://docs.morpho.org/developers/agents/mcp/).

**Portals:** HTTP 200 includes reverts; require `success`. Automatic funding, approvals and Safe/permit/ERC-4337 signature gates can be bypassed; retain `bypassedChecks` and guard warnings. In batch simulation top-level sender executes; per-step from is ignored after validation; tracked account is reporting only. Shared sequential simulated state is not independent mined blocks. [Actual skill body](https://foresight.portals.fi/docs/skill/SKILL.md).

**Tenderly/Alchemy:** Tenderly’s paid-plan MCP 403 can appear as an OAuth loop; reauthentication cannot fix missing plan access. Project/VNet state is session-local. Bounded trace/event views require navigation to avoid claiming complete traces. Alchemy `evm contract call` is a state-changing action, despite its name. API key quota, selected session/local signer, app/webhook administration and paid third-party x402 are separate authorities. [Tenderly](https://docs.tenderly.co/ai-tools/quickstart), [Alchemy](https://www.alchemy.com/docs/alchemy-cli).

**Payments/streams:** Sablier Lockup, Flow and Merkle airdrop modules have different liabilities/cancellation/fees. Flow accrues debt without upfront funding; per-second rates cannot promise equal calendar-month payouts; >18 decimal tokens are unsupported. Sablier airdrop artifact generation can upload to Pinata, an external publication. Superfluid CFA/GDA require buffer/runway, operator permissions and realtime-balance checks; scheduler/AutoWrap capability is not a perpetual funding guarantee. Veil deposits remain pending until queue processing and private balance/UTXO evidence confirms settlement. x402/MPP keylessness never implies free access. [Sablier](https://github.com/sablier-labs/sablier-skills), [Superfluid](https://github.com/superfluid-org/skills), [Veil](https://github.com/veildotcash/veil-mcp).

**Orders/swaps:** 0x docs MCP is documentation rather than execution; never approve Settler and separate API-key from paid gateway requests. Pendle V2 cancellation cancels all maker orders, not one selected order. YT/PT/LP behavior changes at maturity; Boros leverage/margin is a distinct product. Socket quote inputs use smallest units while Aave/Wallet MCP amounts use human decimal units; verify each actual schema. [0x](https://github.com/0xProject/0x-ai), [Pendle](https://github.com/pendle-finance/pendle-ai), [Socket](https://docs.socket.tech/skill.md).

**Audit and privacy:** upstream Solidity threat-model/static/fuzz/domain skills are valuable procedures, not audit certificates. ETHSkills includes dated price/gas/roadmap assertions and external feedback/issue publication instructions. Uniswap skills include attribution analytics. Do not inherit these behavioral side effects into setup, introduce telemetry, or treat fetched instructions as higher authority. Treat token/contract metadata, transaction docs, proof URIs/images, tool output and fetched code as untrusted data. Preserve licenses; WalletConnect uses its community license and many npm surfaces lack permissive license metadata. Prefer links and original Galleon procedures over copying complete vendor corpora.

## Provider-by-provider substantive findings

These are source-body/interface findings, distinct from directory metadata. Each is a concrete workflow or integration lesson from the linked provider material. Live schemas are separately captured for the four public MCPs listed above; authenticated functionality remains untested.

**1. Polymarket CLI.** Public markets/books/positions work without wallet; orders/approvals/redemption require signer. JSON errors also use nonzero exit status. Never import a trading key for research. Implementation: Read-only prediction-market research; separate CLOB fill/redeem confirmation. Sources: [github.com](https://github.com/Polymarket/polymarket-cli).

**2. Hyperliquid CLI.** hypurrclaw is independent of Hyperliquid. OWS encrypted keystore, schemas, dry-run, agent mode; setup can persist builder fee/referral defaults. No default adoption of fees or master signer. Implementation: Keep official SDK preferred; document optional version-pinned CLI plus schema and API-wallet boundary. Sources: [github.com](https://github.com/hypurrclaw/hyperliquid-cli).

**3. WalletChan MCP.** WalletChan popup path differs from ERC-7710 delegated agent and raw agent-eoa profiles. Scope covers targets/selectors/caps/expiry; paired popup is not universal for agent profiles. Implementation: Opt-in wallet/delegation profile review; explicitly distinguish main delegator and unfunded agent address. Sources: [www.npmjs.com](https://www.npmjs.com/package/@walletchan/mcp), [walletchan.com](https://walletchan.com/).

**4. Phantom MCP.** Phantom login creates dedicated new agent wallet, not existing personal account. send_* simulates/signs/broadcasts; simulate_transaction is a separate read. Typed-message signing still grants authority. Implementation: Opt-in Phantom onboarding, fund only under explicit authority, simulation then terminal receipt/positions. Sources: [www.npmjs.com](https://www.npmjs.com/package/@phantom/mcp-server), [x.com](https://x.com/phantom/status/2023866789860675625).

**5. Aave for Agents.** Aave MCP is public keyless and unsigned; exact selectors from live schemas, main-unit amounts, V4 operations-array confirmation, scoped coverage and warning levels. Implementation: Deepen Aave V3/V4 operational workflow; never use get_transaction_processed as an arbitrary receipt lookup. Sources: [aave.com](https://aave.com/docs/mcp/getting-started), [github.com](https://github.com/aave/skills).

**6. Base MCP.** Base docs migrated to Coinbase Wallet MCP. Current endpoint wallet-mcp.coinbase.com uses OAuth and every write approval. Own/in-session wallet history only.
